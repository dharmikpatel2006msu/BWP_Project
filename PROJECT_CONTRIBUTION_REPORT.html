🎨 2. Frontend Development Team (50% Workshare)

The Frontend Team engineered a zero-dependency, responsive interface using Vanilla HTML5, Vanilla CSS3 (custom design system), and Modular JavaScript (ES6). Third-party CSS frameworks were eliminated to ensure sub-second rendering, prevent supply-chain vulnerabilities, and provide pixel-perfect print adherence for Section 65B certificates.

Viva Voce Defense Q&A

Q: How do you protect routes across independent HTML pages without a single-page router?
A: On page initialization, api.js and auth.js verify the signed JWT stored in localStorage. If absent or expired, the user is redirected to index.html. User roles are parsed to restrict unauthorized page access before rendering.
Q: How do you handle file uploads in Vanilla JS without data corruption?
A: Using native FormData streamed as multipart/form-data via fetch, preserving exact raw byte integrity for backend SHA-256 computation.

Q: What is the purpose of the Section 65B certificate?
A: Under Indian Evidence Law, digital evidence is admissible in court only if certified regarding electronic integrity and device custody. Our page dynamically produces this compliant certification.

The Backend Team architected an enterprise REST API on Node.js, Express.js, Supabase (PostgreSQL), Multer, and Node Crypto, providing strict RBAC authorization, streaming SHA-256 hashing, immutable custody auditing, and XML reporting.

Viva Voce Defense Q&A

Q: Why did you choose PostgreSQL over MongoDB?
A: Digital evidence requires strict ACID guarantees and foreign key referential integrity so that custody records can never be orphaned or modified without audit traces.

Viva Voce Defense Q&A

Q: Why use stream hashing instead of readFileSync?
A: readFileSync loads whole files into RAM, causing memory crashes on large forensic files (e.g. video files over 100MB). Streams process data in sequential 64KB chunks with constant, low RAM usage.
